# Онлайн-деканат

Сервис проверяет студенческие документы: справки об обучении, справки о практике, заявления на академический отпуск.

### Как устроена обработка

Обработка выполняется локально на CPU. PaddleOCR/PaddleX использует модели `PP-OCRv5_mobile_det` и `eslav_PP-OCRv5_mobile_rec`; резервный движок - Tesseract с языками rus/eng. OpenCV и Pillow обрабатывают изображения, PyMuPDF растеризует PDF. Поля извлекаются по меткам и нормализуются кодом. Для установки зависимостей и загрузки весов нужен интернет.

### Ограничения демо

- Основной вход: JPG, PNG или одностраничный PDF до 20 МБ. Подпись и печать проверяются на наличие, не на подлинность. Качество на произвольных реальных снимках требует отдельной оценки.
- Кабинеты работают без аутентификации, пользователь сам выбирает роль. Для ряда операций API, включая чтение и удаление документа, нет проверки владельца. Демонстрация рассчитана на синтетические данные; перед использованием реальных документов нужны аутентификация и проверки доступа.
- Заявление о переводе (`transfer_application`) - добавленная командой заглушка для демонстрации нового типа через YAML. Оно не входит в три типа автопроверки; ссылки на раздел 4 условные и не устанавливают требования к переводу.

Что он умеет:

- распознаёт текст на фото, скане или PDF (OCR работает локально, без внешних сервисов);
- раскладывает данные по полям: ФИО, дата выдачи, номер, подпись, печать и т. д.;
- проверяет, всех ли сведений хватает по Положению, и ссылается на нужные пункты;
- отвечает на вопросы по документу и честно объясняет, почему поле не найдено: в документе пусто или метку не удалось прочитать на снимке;
- позволяет студенту исправить ошибку OCR в поле: исходное распознанное значение сохраняется и видно деканату;
- даёт студенту кабинет с историей документов и ответами деканата;
- даёт деканату кабинет со входящими заявками, кратким анализом ИИ и кнопками "Принять" / "Вернуть на доработку" / "Отклонить";
- связывает исправленную версию документа с прежней заявкой и показывает деканату, что изменилось;
- присылает решение деканата студенту в Telegram и ведёт журнал заявок в CSV.

Всё это доступно на сайте и через Telegram-бота [@Ci_Deckanat_bot](https://t.me/Ci_Deckanat_bot). Бот принимает документы, отвечает на вопросы, отправляет документ в деканат и показывает историю; для кабинета даёт ссылку на сайт.

## Бонусные возможности

- **Автоопределение типа документа.** На сайте вкладка «Автоматически», в боте кнопка «Определить автоматически». Тип выбирается по заголовку и меткам полей на снимке; при низкой уверенности сервис предупреждает и предлагает проверить выбор. Логика в `core/dekanat_core/classify/doc_type.py`.
- **Плохие снимки.** Перед OCR снимок проходит предобработку: исправление ориентации страницы, выравнивание перспективы, удаление теней и бликов, поворот при наклоне до 30°, увеличение мелкого текста. Код в `core/dekanat_core/preprocess/`. Проверить устойчивость можно бенчмарком на открытом наборе с аугментациями (поворот, перспектива, тень, блик, низкое разрешение, шум, размытие):

  ```powershell
  python scripts/robustness_bench.py --limit 30
  ```

- **Новый тип документа без кода.** Типы описаны YAML-файлами в `config/doc_types/`, по одному файлу на тип. Чтобы добавить свой: скопируйте любой файл из этой папки, задайте `key`, `title`, ключевые слова для автоопределения в `detect` и список `fields` (у каждого поля `key`, `label`, `aliases` для вопросов, `type` и `rule` с номером пункта Положения), затем перезапустите сервис. Тип появится на сайте, в боте и в `/api/v1/doc-types`. Образец с комментариями: `config/doc_types/transfer_application.yaml`. Допустимые типы полей перечислены в `core/dekanat_core/config/schema.py`.
- **Подсветка поля на снимке.** На странице документа найденные поля обведены рамками, клик по полю в карточке или по источнику в ответе подсвечивает его на изображении; к ответу прикладывается фрагмент снимка с полем. В боте команда `/photo` присылает снимок с разметкой, а кнопки под карточкой полей показывают фрагмент нужного поля.

## Из чего состоит проект

| Папка | Что внутри |
|---|---|
| `core/` | ядро: предобработка снимка, OCR, извлечение полей, проверка по правилам, ответы на вопросы |
| `backend/` | Django REST API и раздача собранного сайта |
| `frontend/` | сайт на React + Vite + Tailwind |
| `bot/` | Telegram-бот на aiogram |
| `config/` | описание типов документов (YAML), правила, словари |
| `data/` | тестовые документы, вопросы, эталонные ответы, скрипт оценки |
| `scripts/` | загрузка моделей OCR, пакетный прогон, бенчмарки, туннель для сайта |
| `tests/` | тесты ядра |
| `docker/` | Dockerfile для бэкенда и бота |

## Запуск через Docker

Самый простой путь: Python и Node ставить не нужно, достаточно Docker Desktop и Git.

1. Скопируйте настройки:

   ```powershell
   copy .env.example .env
   ```

   В `.env` заполните `BOT_TOKEN` (токен от @BotFather), если нужен бот. Остальное можно не трогать.

2. Запустите Docker Desktop, затем соберите и запустите:

   ```powershell
   docker compose up --build db backend
   ```

   Поднимутся база PostgreSQL и бэкенд с собранным сайтом. Для запуска также и бота заполните `BOT_TOKEN` и выполните `docker compose up --build`. При первой сборке скачиваются зависимости и модели OCR. Бэкенд сам создаёт и применяет миграции при старте.

3. Откройте http://localhost:8000. В логе контейнера `backend` видны адреса сайта, кабинета и документации API.

Полезные команды:

```powershell
docker compose up -d db backend # запустить сайт и базу в фоне
docker compose logs -f backend
docker compose down           # остановить, данные базы сохранятся
docker compose down -v        # полный сброс: удалить тома базы и загруженных документов
```

Чтобы ссылки из бота открывались с телефона, нужен публичный адрес сайта, см. раздел "Доступ с телефона". Скрипт туннеля запускается на компьютере, не в Docker: бот в контейнере читает адрес из папки `runtime/`, которая в него подключена.

## Ручная сборка

Подходит для разработки: можно править код и сразу видеть результат.

### Что нужно установить

- Python 3.12 (с 3.13 и новее PaddleOCR не работает)
- Node.js 22.12 или новее (в lock-файле есть зависимости, требующие Node 22)
- Docker Desktop (только для базы PostgreSQL; без него можно работать на SQLite, см. шаг 2)
- Git
- Tesseract OCR (по желанию): запасной движок, который включается, если PaddleOCR прочитал снимок плохо. Без него всё работает на PaddleOCR. Установщик для Windows: https://github.com/UB-Mannheim/tesseract/wiki, после установки укажите путь в `TESSERACT_CMD` в `.env`, если он отличается от `C:\Program Files\Tesseract-OCR\tesseract.exe`. Языковые файлы rus/eng скачивает `scripts/download_models.py`.

Проверить версии:

```powershell
py -3.12 --version
node --version
docker --version
```

### Шаги 

Все команды выполняются в PowerShell из корня проекта.

1. Настройки:

   ```powershell
   copy .env.example .env
   ```

   В `.env` заполните `BOT_TOKEN`, если нужен бот. `DATABASE_URL` оставьте как есть, он указывает на базу из Docker.

2. База данных (Docker Desktop должен быть запущен):

   ```powershell
   docker compose up -d db
   ```

   PostgreSQL поднимется в контейнере и будет доступен на порту 5433 (не 5432, чтобы не конфликтовать с локально установленным PostgreSQL). Данные хранятся в Docker-томе `pgdata`.

   Без Docker можно обойтись SQLite: впишите в `.env` строку `DATABASE_URL=sqlite:///db.sqlite3` (файл появится в папке `backend`, откуда запускается `manage.py`). Для демо этого достаточно, для многопользовательской работы лучше PostgreSQL.

3. Окружение Python:

   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install -r requirements/dev.txt
   ```

   Дальше все команды выполняются в этом же окне с активированным окружением (в начале строки видно `(.venv)`).

4. Модели OCR (загружать один раз):

   ```powershell
   python scripts/download_models.py
   ```

5. Таблицы в базе:

   ```powershell
   cd backend
   python manage.py makemigrations documents
   python manage.py migrate
   cd ..
   ```

   Файлы миграций в git не хранятся, первая команда создаёт их локально. После изменения моделей повторите обе команды.

6. Сайт:

   ```powershell
   cd frontend
   npm ci
   npm run build
   cd ..
   ```

   Сборка попадает в `frontend/dist`, бэкенд раздаёт её сам. Для разработки фронтенда вместо `build` запустите `npm run dev`: сайт будет на http://localhost:5173 с автообновлением, запросы к API уйдут на бэкенд.

7. Бэкенд:

   ```powershell
   cd backend
   python manage.py serve
   ```

   В консоли появятся адреса сайта, кабинета и документации API. Первые секунды после старта прогревается OCR. Для отладки Django-кода можно использовать `python manage.py runserver`: он перезапускается при правках. Для демонстрационного запуска предусмотрен `serve` на Waitress.

8. Бот (по желанию), в новом окне PowerShell с активированным окружением:

   ```powershell
   python -m bot
   ```

   Команды бота: `/start`, `/new`, `/check`, `/fields`, `/photo`, `/text`, `/type`, `/submit`, `/history`, `/rules`, `/site`, `/help`. Кнопка "Открыть приложение" и команда `/site` присылают ссылку на сайт.

   Бот сам заводит профиль студента по Telegram-аккаунту: загрузки из бота попадают в "Мои документы" на сайте, `/submit` отправляет текущий документ в деканат, `/history` показывает последние документы и решения. Когда деканат принимает решение, бот присылает его в чат (бот раз в несколько секунд забирает очередь уведомлений с бэкенда). Уведомление приходит, если документ был загружен через бота; документы, загруженные только на сайте, в Telegram не отслеживаются.

Полезные адреса после запуска:

- http://localhost:8000 - сайт
- http://localhost:8000/cabinet - кабинет
- http://localhost:8000/api/docs/ - описание API (Swagger)
- http://localhost:8000/api/v1/health - состояние сервиса

## Доступ с телефона

Сайт работает на вашем компьютере, с телефона он не виден. Чтобы ссылки из бота открывались, нужен публичный адрес. Его держит скрипт (запускается на компьютере, при любом способе запуска):

```powershell
python scripts/tunnel_keeper.py
```

Он поднимает туннель через serveo, записывает адрес в `runtime/site_url.txt` и в `SITE_URL` в `.env`. Бот читает адрес при каждом нажатии, перезапускать его не нужно. Если туннель упал, скрипт переподключится сам.

Доступность туннеля зависит от сети и провайдера; при блокировке может понадобиться VPN. Провайдер может показывать страницу подтверждения перехода. Туннель открывает доступ к демонстрационному API извне: учитывайте ограничения кабинетов, описанные выше.

Если сайт переедет на сервер с доменом, туннель не нужен: впишите домен в `SITE_URL`.

## Как пользоваться кабинетом

Входа по паролю нет, это демонстрационный режим.

1. Откройте http://localhost:8000/cabinet.
2. Выберите роль (студент или деканат) и введите имя.
3. Если вы уже входили под этим именем, откроется прежний кабинет с историей.

Студент:

- загружает документ на главной странице;
- если OCR ошибся, исправляет значение в карточке полей (кнопка с карандашом). Исходное значение OCR сохраняется, деканат видит оба; подпись и печать вручную отметить нельзя;
- на странице документа нажимает "Отправить в деканат". Если по проверке чего-то не хватает, сервис предупредит об этом до отправки;
- в кабинете видит статус заявки и комментарий деканата;
- после "Нужно исправить" или "Отклонено" нажимает "Загрузить исправленную версию": новая версия связывается с прежней и сразу уходит в деканат.

Деканат:

- в кабинете видит входящие заявки, новые подсвечены; исправленные версии и ручные правки помечены;
- открывает заявку, читает анализ ИИ: чего не хватает и почему (пусто в документе или не распознано), какие поля студент ввёл вручную;
- для исправленной версии видит таблицу "что изменилось" по сравнению с прежней;
- нажимает "Принять", "Вернуть на доработку" или "Отклонить"; для возврата и отказа выбирает причину из предложенных ИИ или пишет свою;
- скачивает журнал заявок в CSV (ссылка над списком).

Чтобы посмотреть обе роли на одном компьютере, откройте второе окно браузера в приватном режиме.

## Проверка качества на тестовом наборе
```powershell
python scripts/predict.py --manifest data/documents.json --questions data/questions.json --base data --input pdf --out results.json --reference data/reference_results.json
```

В конце скрипт выведет три метрики: точность полей, точность проверки и точность ответов.

Для закрытого набора организаторов (тот же формат манифеста и вопросов) команда та же, только без `--reference`:

```powershell
python scripts/predict.py --manifest <папка>/documents.json --questions <папка>/questions.json --base <папка> --input pdf --out results.json
```

Если в манифесте нет PDF, укажите `--input image`. Получившийся `results.json` и есть файл для сдачи; скрипт проверяет его по `data/results.schema.json`.

## Очистка данных

Удалить всё, что загрузили пользователи (документы, вопросы, заявки, уведомления, профили, файлы в `backend/media/uploads`), таблицы и миграции остаются:

```powershell
cd backend
python manage.py reset_data --yes          # --keep-profiles, чтобы оставить профили кабинета
```

Удалить только анонимные загрузки старше суток (не привязанные к кабинету и не отправленные в деканат):

```powershell
python manage.py cleanup_uploads --days 1
```

В Docker те же команды выполняются через `docker compose exec backend python manage.py reset_data --yes`. Полный сброс базы вместе со схемой и загруженными файлами: `docker compose down -v`.

## Тесты

```powershell
python -m pytest                              # ядро, проходит за секунды
python -m pytest -m slow                      # сквозные тесты с OCR; полный прогон требует исходных PNG
cd backend
python manage.py test documents               # API и кабинет, нужны база и модели OCR
```

Тесты бэкенда создают отдельную тестовую базу, рабочие данные не трогают. Если Docker с PostgreSQL не запущен, их можно прогнать на SQLite:

```powershell
$env:DATABASE_URL = "sqlite:///$PWD/test.sqlite3"; python manage.py test documents
```

## Структура .env

| Переменная | Для чего |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `API_BASE_URL` | адрес бэкенда для бота, по умолчанию http://localhost:8000 |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT` | параметры контейнера с базой |
| `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS` | настройки Django |
| `DEKANAT_WARMUP` | прогрев OCR при старте бэкенда (1 по умолчанию, 0 отключает) |
| `TESSERACT_CMD`, `TESSDATA_PREFIX` | путь к `tesseract.exe` и к языковым файлам, если Tesseract установлен нестандартно |
| `API_THROTTLE` | лимит запросов к API на один адрес, по умолчанию 600/min |
| `SITE_URL` | публичный адрес сайта для ссылок из бота |
| `DEKANAT_ADMIN_TOKEN` | необязательный токен: если задан, бот присылает его в `X-Admin-Token`, чтобы забирать очередь уведомлений |
| `NOTIFY_INTERVAL` | как часто бот опрашивает очередь уведомлений, секунды (по умолчанию 4) |
| `TUNNEL_PROVIDER`, `TUNNEL_NAME` | провайдер и имя туннеля для `tunnel_keeper.py` |

## Если что-то не работает

- Бэкенд не подключается к базе: проверьте, что Docker Desktop запущен и контейнер поднят (`docker compose ps`), а в `DATABASE_URL` порт 5433. Либо переключитесь на SQLite (шаг 2 ручной сборки).
- Бэкенд падает на старте с ошибкой про отсутствующую колонку или таблицу: после обновления кода выполните `python manage.py makemigrations documents` и `python manage.py migrate` (в Docker это делается само).
- В `/api/v1/health` движок `tesseract` показан как `not_loaded`: это нормально, запасной движок загружается только при первой необходимости, а если Tesseract не установлен, используется только PaddleOCR.
- Сайт показывает "Фронтенд не собран": выполните шаг 6 ручного запуска.
- Документ долго обрабатывается: первый запуск после старта медленнее, пока прогревается OCR.
- Бот пишет, что адрес сайта не настроен: запустите `tunnel_keeper.py` или заполните `SITE_URL`.
- Бот не отвечает, а в логе `TelegramConflictError`: запущено два экземпляра бота с одним токеном, оставьте один.
- На телефоне не открывается ссылка из бота: проверьте работу туннеля, актуальность `SITE_URL` и доступность провайдера из вашей сети.
